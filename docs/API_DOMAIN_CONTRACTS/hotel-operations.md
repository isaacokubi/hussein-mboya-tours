# Hotel catalog, availability and reservation contracts

## Entries 289–300: `/api/hotels` routes

**Status: SOURCE-TRACED.** Route registration and guards: `server/routes/hotelRoutes.js`. Public handlers are in `hotelController.js` and `hotelAvailabilityController.js`; admin writes use `adminHotelCreationController.js`; booking creation uses `hospitalityInventoryConcurrencyController.js`; safe lists use `hospitalityAdminController.js`; legacy-to-PMS import uses `hospitalityInventorySyncController.js`; booking update uses `hotelController.js` behind `paymentMutationGuard.js`. Models include `Hotel`, `HotelRoomType`, `HotelBooking`, `HospitalityRoomBlock`, `HospitalityRatePlan`, and customer/user records.

Routes with `protect, managerOnly` require manager authorization; booking create/list/update require JWT, while catalog list/availability/detail are unauthenticated. Handler code obtains tenant from `req.tenantId` or authenticated user's tenant. Hotel endpoints do not declare a local `resolveTenant` router middleware, so public operation depends on upstream tenant resolution/configuration.

- `GET /api/hotels`: query `city` (escaped exact case-insensitive match) and `featured=true`; requires tenant and returns active hotels, featured/name sorted, each with active room types by nightly rate. 200 `{success:true,data}`. No pagination.
- `GET /api/hotels/availability`: query `hotelId`, `checkIn`, `checkOut`, optional `ratePlanId`. Missing/invalid tenant/date/property values 400; inactive/missing hotel 404. Computes nights, overlapping non-cancelled/non-no-show bookings and active room blocks; selects valid active rates by date/min/max night, returns room availability, rates, stop-sell and stay total under `{success:true,data:{hotel,checkIn,checkOut,nights,roomTypes}}`. This is a read-time quote, not a reservation.
- `GET /api/hotels/admin/catalog`: `protect, managerOnly`; optional `status`; returns tenant hotels and all room types, newest first, in `{success:true,data}`. Despite legacy `listAdminHotels` existing in `hotelController.js`, route mounts `listAdminHotelsSafe` with batched room hydration.
- `POST /api/hotels/admin/catalog`: manager only. Body fields consumed by `createAdminHotel`: required `name`, `city`, `location`; optional slug, description/address/county/country, coordinates, starRating (default 3), amenities/images, contacts, check-in/out defaults 14:00/11:00, policy, status (draft/active/inactive else draft), featured boolean, currency default KES. Coordinates must be finite/in range, star rating integer 1–5, email valid. Tenant-unique slug gets numeric suffix; creates Hotel and returns 201 `{success,message,data}`. Duplicate key is 409.
- `PATCH /api/hotels/admin/catalog/:id`: manager only. Updates allowlisted hotel fields; validates required name/city/location, 1–5 star rating, email and coordinates; arrays are cleaned/capped; status normalizes to allowed values or draft; currency uppercases/defaults KES; changed name regenerates unique slug. Missing hotel 404, invalid data 400, duplicate 409; success 200 `{success,message,data}`.
- `POST /api/hotels/admin/catalog/:hotelId/rooms`: manager only. Body is normalized to name/description, capacity defaults 2 adults/1 child, beds/amenities, required numeric totalRooms, availableRooms default total, nightlyRate, mealPlans, currency KES, status active. Enforces name, total >=1, available 0..total, rate >=0, integer adult capacity >=1, children >=0; empty meal plans default `room_only`. Tenant hotel must exist; 400 invalid data, 404 hotel, 409 duplicate room type; success 201.
- `PATCH /api/hotels/admin/rooms/:id`: manager only. Updates allowlisted room fields, coerces numeric capacity/inventory/rate, cleans/caps arrays, normalizes currency/status. Requires name, available <= total, nonnegative rate, integer capacities; missing room 404, invalid 400, duplicate 409; success 200. Does not enforce `totalRooms` minimum 1 in this update handler (schema validation may add constraints).
- `POST /api/hotels/admin/sync-inventory`: manager only; no body fields. Reads tenant `AccommodationInventory`, and for each row with property/room names creates missing Hotel/HotelRoomType or overwrites matched room inventory/rate/status. Returns processed count and created/updated counts. It is iterative and not transactional; partial synchronization can persist if a later row fails.
- `POST /api/hotels/bookings`: authenticated. Body requires `hotelId`, `roomTypeId`, `checkIn`, `checkOut`; defaults rooms/adults to 1 and children 0; optional selected rate plan, taxes/fees, guest/customer fields, linked booking, meal/bed/diet/accessibility/arrival/transfer/special requests/source. Checks active tenant hotel/room, date ordering, integer room and guest counts, capacity. Acquires a room inventory version through atomic compare-and-increment with up to three retries, then checks overlapping bookings and blocks, chooses valid rate, rejects stop-sell or insufficient inventory (409), resolves/creates Customer when possible, calculates subtotal from nights×rooms×rate plus body taxes/fees, creates pending HotelBooking, ensures invoice, and returns 201 `{success:true,data,invoice,paymentRequired}`. There is no idempotency key or transaction across version bump, booking creation, and invoice creation. **Concurrency limitation found in source:** the guard increments `inventoryVersion` but holds no lock/lease through subsequent overlap check and insert. A competing caller whose first CAS loses can reread the new version and acquire it while the first is still processing; therefore this alone does not prove overbooking is prevented. No controller-level concurrency test was found in reviewed tests.
- `GET /api/hotels/bookings`: authenticated, handler further permits customer or staff roles. Optional `status`, `customerId`; customer is restricted to own `user` ID. Safe handler validates references and hydrates hotel/room/customer/user from same tenant. Returns `{success:true,data}`; access denied 403.
- `PATCH /api/hotels/bookings/:id`: authenticated then `paymentMutationGuard` rejects any body containing `paymentStatus` with 403. Owner customer can only change `specialRequests`; staff roles admin/manager/tour_manager/tourmanager/agent may change notes and status. Status transitions: pending→confirmed/cancelled/no_show; confirmed→checked_in/cancelled/no_show; checked_in→checked_out; terminal states cannot move. Missing 404, owner/role or protected fields 403, invalid transition 409; success `{success:true,data}`.
- `GET /api/hotels/:id`: public but tenant-required; accepts ObjectId or slug, returns active hotel plus active room types, or 404. Path route is registered last so it does not capture the preceding static routes.

All controller errors not explicitly returned are passed to centralized middleware. Existing hospitality lifecycle tests cover payment completion rather than the hotel room inventory race. No live booking, external PMS call, or payment was executed. The documented synchronization endpoint is an internal database migration-style operation; it does not call an external hotel PMS.
