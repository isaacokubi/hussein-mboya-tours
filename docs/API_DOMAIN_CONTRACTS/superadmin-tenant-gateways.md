# Super Admin tenant M-Pesa gateway and status APIs

All routes in this contract are mounted by server/routes/superAdminRoutes.js under /api/superadmin and inherit protect then superAdminOnly.

## Tenant gateway wrapper and isolation

The M-Pesa controller is created through createSuperAdminMpesaGatewayController with injectable organization/gateway models, encrypt/decrypt functions, tenant-scope runner, settings validator, HTTP client and clock. Each operation first validates req.params.tenantId as a Mongo ObjectId, then loads the tenant in explicit platform bypass context. Missing tenants and protected platform/system organizations return 404. For accepted tenants, the operation runs inside a tenant-specific context with role admin and bypass false. PaymentGatewayConfig is tenant-scoped and the lookup key is {tenantId,provider:"MPESA"}.

## GET /api/superadmin/tenants/:tenantId/mpesa — inventory 427 and 428

Handler getSuperAdminTenantMpesa. Optional query parameter environment selects sandbox or production; otherwise the stored config environment is used, defaulting to sandbox. It reads the tenant's MPESA PaymentGatewayConfig and returns 200 {success:true,tenant:{id,name,slug},data}. data is generated by safeMpesaGatewayView and contains provider, selected environment, enabled, accountName, environment-specific shortcode/callbackUrl, configured boolean, per-secret configured booleans and optional validation metadata. Raw encrypted credentials and decrypted secret values are not returned. If no config exists, an unconfigured safe view is returned. Invalid tenant IDs return 400; missing/protected tenants return 404. Unexpected errors go to next(error).

## PUT /api/superadmin/tenants/:tenantId/mpesa — inventory 429 and 430

Handler saveSuperAdminTenantMpesa. Body requires environment ("sandbox" or "production") and enabled (boolean). Optional consumerKey, consumerSecret, passkey, callbackUrl, shortcode and accountName must be strings when supplied; other types return 400. Only the selected environment's shortcode, callback URL and non-empty secret values are updated. Secret values are encrypted using AES-256-GCM before persistence; the encryption key is derived from PAYMENT_CREDENTIAL_ENCRYPTION_KEY or JWT_SECRET. Empty/omitted secrets preserve existing encrypted values. If enabling, shortcode, all three credentials and callback URL must be present. Callback validation requires public HTTPS, no credentials/hash/query/non-443 port, exact /api/mpesa/callback path, non-local hostname and non-IP host; sandbox callback origin must match the configured sandbox/shared callback host.

Success is 200 {success:true,message:"Tenant M-Pesa settings saved securely.",data:safeMpesaGatewayView(...)}. Validation failures return 400 with a message. The update is an upsert keyed by tenantId/provider and uses runValidators. It records updatedBy. Raw credentials are never included in the response.

## POST /api/superadmin/tenants/:tenantId/mpesa/validate — inventory 431 and 432

Handler validateSuperAdminTenantMpesa. The route adds express-rate-limit with a 15-minute window and limit 5 before the handler. The body field environment must select sandbox or production. It loads the tenant gateway config and environment-specific settings. Missing config/invalid environment returns a JSON result status "invalid"; missing shortcode, encrypted credentials or valid callback returns status "incomplete"; decryption failure returns "invalid". These are result statuses inside a success:true envelope, not HTTP error statuses.

For complete settings, it decrypts Consumer Key/Secret and passkey (passkey is decrypted to validate ciphertext), then calls the Daraja OAuth endpoint from getMpesaUrls(environment) with Basic auth, 8-second timeout and redirects disabled. An access_token yields status "connected", remoteVerified true and message explicitly says no payment was initiated. Missing token yields provider_error; timeout yields unverified; 401/403 yields invalid_credentials; other provider/network errors yield provider_error. The handler always uses {success:true,data:{status,environment,timestamp,remoteVerified,message}} for these validation outcomes. It verifies OAuth connectivity only; it does not execute a payment or validate STK push/callback settlement.

## DELETE /api/superadmin/tenants/:tenantId/mpesa — inventory 433 and 434

Handler disableSuperAdminTenantMpesa. It updates the tenant's MPESA config to enabled:false and records updatedBy. Missing configuration returns 404. Success is 200 {success:true,message:"Tenant M-Pesa gateway disabled."}. It does not delete credentials or the configuration document.

## PATCH /api/superadmin/tenants/:id/status — inventory 435 and 436

Handler updateTenantStatus. Body fields read: status, plan, periodDays and transactionReference. Invalid tenant ObjectId returns 400; status must be active, suspended, trial or cancelled; missing tenant returns 404. For status active, plan defaults to the organization's current plan or starter and must be one of the four TENANT_PLANS. periodDays defaults to 30 when non-positive/invalid and is floored; activateTenantSubscription clamps its own effective period to 1–3660 days. The handler passes provider manual and transactionReference to that service, then returns {success:true,tenant,subscription:{status:"active",plan,periodStartsAt,periodEndsAt},message}. It does not create or require a SubscriptionPayment record or require a non-empty verified payment reference on this status route. Thus this is a manual administrative activation path, not proof that payment was received.

For suspended/trial/cancelled, it updates only Organization.status with validators and returns {success:true,tenant,message}. It does not synchronously update the separate Subscription document in this branch, so organization and subscription status can temporarily or persistently diverge unless another workflow reconciles them. Errors go to next(error).

## Test evidence and limitations

No focused test for createSuperAdminMpesaGatewayController or updateTenantStatus was found in the searched paths. Source evidence covers route-level rate limiting, tenant context isolation, credential encryption, callback URL validation, OAuth-only verification, disable semantics and status activation. No credentials were saved, no Daraja request was sent, no tenant gateway was changed and no payment was initiated during this review.
