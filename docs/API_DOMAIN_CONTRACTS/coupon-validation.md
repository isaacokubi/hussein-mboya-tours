# Coupon validation API contract

`POST /api/coupons/validate` (entry 209) is mounted by `couponRoutes.js` with `resolveTenant` → `protect`; any active authenticated tenant role may validate, with no admin permission, branch restriction or rate limiter. JSON body requires string `code` and positive numeric-coercible `amount`; missing/wrong type code or missing/null/NaN/nonpositive amount returns 400. The controller trims and uppercases code and calls `applyCoupon(code, Number(amount))`.

Success HTTP 200 `{success:true,message:"Coupon validated successfully.",data:{code,originalAmount,discount}}` even when the coupon is invalid. `discount` is the service result object `{valid,discount,finalAmount,coupon,message}` rather than just a number. Invalid/missing/inactive code, expiry, usage limit and minimum purchase are represented inside that result; they do not cause non-200 errors. Fixed/percentage discount is capped to amount and rounded to two decimals. Errors thrown by tenancy/database go to centralized error handling.

**Implementation/schema mismatch:** `couponService.applyCoupon` checks `coupon.expiryDate` and `coupon.minimumAmount`, but `Coupon` schema defines `expiresAt` and `minimumBookingAmount`; absent legacy fields mean those checks may be skipped, allowing expired or below-minimum coupons. The service also does not check `startDate`, does not call `canBeUsed`, and does not increment `usedCount`; this endpoint is validation only, not reservation/application. There is no per-user eligibility/history check or idempotency/usage reservation. The admin coupon API has separate code paths and its schema behavior is documented in [admin coupon contracts](admin-coupons.md).

Sources: `couponRoutes.js`, `couponController.js`, `couponService.js`, `Coupon.js`. The first-party `client/src/api/couponApi.js` wrappers found call admin paths; no public checkout caller for `/coupons/validate` was found. No focused validation endpoint test identified.
