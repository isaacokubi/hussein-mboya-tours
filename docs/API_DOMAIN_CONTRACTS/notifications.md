# Notification API contracts

## Entries 334–338

**Status: SOURCE-TRACED.** `server/routes/notificationRoutes.js` applies `resolveTenant` and `protect`; recipient listing and internal send add a role middleware for admin/super-admin/tour-manager/manager aliases. Handlers: `server/controllers/notificationController.js`; records: `Notification`, plus tenant `User`, `Staff`, `Role`. No focused tests for these route handlers were identified.

- `GET /api/notifications/recipients?roles=...`: role middleware and controller repeat a staff-role check. Default roles: guide, driver, agent, admin, manager. Comma-separated requested aliases are normalized; unknown roles yield no matches. Reads tenant role docs/users and active Staff; maps linked staff users and deduplicates. Returns `{success:true,recipients}` with selected identity and role fields. No mutation or external delivery.
- `POST /api/notifications/internal`: same role guard. Body requires trimmed `title` and `message`; optional `recipientIds[]`, `roles[]`, `type` default system, `priority` default normal, `actionUrl` default empty. IDs failing ObjectId validation are silently discarded; role aliases expand to role names. At least one valid ID or supported role group is needed (400); active tenant recipients are selected and missing recipients return 404. Creates one Notification per recipient with internal/sent metadata, normalized type/priority fallbacks, unread/unarchived state; returns 201 `{success:true,message,count}`. This persists notifications only; this handler does not call SMS/email/WhatsApp despite imports used elsewhere in the controller.
- `GET /api/notifications` and alias `GET /api/notifications/mine`: both call `getNotifications`. Query page defaults 1/minimum 1; limit defaults 20/clamps 1–100; `unread=true` filters unread; optional `type` exact filter. Reads only the authenticated recipient's unarchived records, newest first, returns 200 `{success,page,limit,total,pages,count,notifications}`. The database filter does not explicitly include tenantId, but is constrained by recipient user ID.
- `PUT /api/notifications/:id/read`: validates ObjectId (400), finds unarchived notification belonging to the authenticated user (404 otherwise), invokes model `markAsRead()` and returns 200 `{success,message,notification}`. No body fields. Errors use central middleware.

Internal recipient selection and user-owned reads are source-scoped as above. A role guard alone does not establish permissions beyond listed roles. No external notifications are sent by the internal endpoint. Live delivery and persistence were not exercised.
