# Canonical admin dashboard metrics

## `GET /api/admin/dashboard/metrics` and `GET /api/admin/dashboard`

Both mounted aliases call `getDashboardMetrics`; the first is the explicit metrics compatibility path and the second is the canonical frontend caller.

- **Access/request:** Router first resolves tenant. Each GET then runs `protect` → `adminOnly` → `authorize("admin.dashboard")`. The handler requires tenant context. No path/query/body fields.
- **Tenant and common filter:** Uses explicit `{tenantId,...}` filters and non-deleted predicates for most counts; recent Booking and User/Staff/Agent/Vehicle/Tour/Destination operations are tenant-scoped. Dashboard reads run concurrently and are not one consistent transaction.
- **Metrics reads:** Counts tenant users/customers excluding blocked and soft-deleted accounts; active staff/guides/drivers; agents, approved and pending agents; active vehicles by available/assigned/maintenance; non-deleted tours/destinations; non-deleted bookings by total and pending/confirmed/completed/cancelled/refunded status; and non-deleted Payments by total/completed/pending/failed buckets. Payment completed statuses include paid/completed/success; pending includes pending/processing/partial; failed includes failed/cancelled.
- **Financial data:** `revenue` comes from `getBookingRevenueMetrics(req)`, whose revenue value calls `getPostedRevenueTotal()`; response copies that value to `grossRevenue`, sets `refundedRevenue:0`, and labels `revenueBasis:"posted_journals"`. Separately, `monthlyRevenue` comes from `getPostedRevenueReport()`, which matches tenant JournalEntry documents with status posted, joins same-tenant active revenue ChartOfAccount rows and groups journal-line net credits by month. Thus top-level total and monthly series both use posted journals. The booking service also counts paid bookings, but the controller does not use that count.
- **Other calculations:** Booking status aggregation is returned in both `status` and `statusData`. Conversion is (confirmed + completed) / all non-deleted bookings, rounded to one decimal. Average booking value includes all non-deleted bookings. Customer rating averages tenant reviews. Popular tours use paid booking statuses, exclude cancelled/refunded bookings and soft-deleted tours, rank by paid booking count/revenue, limit five, and calculate booking-value-based revenue net of the Booking refundAmount field. Recent five bookings are normalized from populated customer/user, snapshots, contact, and tour/custom-tour fallback data.
- **Success:** HTTP 200 includes `{success:true,scope:{tenantId,type:"tenant"},data:{...metrics},timestamp}`. Exact data keys are listed above and in the controller: counts, payment stats, revenue fields, conversion, averageBookingValue, customerRating, topTour, popularTours, status/statusData, monthlyRevenue, recentBookings, summary.
- **Failures:** Caught errors return `{success:false,message}` with `error.status || 500`; message is sanitized with `publicErrorMessage`. Reads only; no dashboard mutation or external provider call.
- **Frontend:** `client/src/api/adminApi.js#getDashboard` calls `/admin/dashboard`; no distinct frontend caller for `/metrics` was found.

The metric contract combines operational counts, Payment-document status counts, posted-journal revenue, and Booking snapshot calculations for popular-tour ranking. The top-level posted revenue and popular-tour booking value therefore have different bases; the controller also reports refundedRevenue as zero rather than calculating posted refunds.
