# Cash payment initiation contract

`POST /api/payments/cash` (inventory entry 198) is mounted from `cashPaymentRoutes.js` under `/api/payments/cash`. Middleware is `resolveTenant` → `protect` → route-local 10 requests / 15 minutes rate limiter → `createCashPayment`. Requires active authenticated tenant user and tenant context; controller permits only the authenticated booking owner (`booking.user` or `booking.customer` matching User ID), with no staff override.

Body reads `bookingId` (required in effect; missing/unmatched booking returns 404) and optional `amount`. It loads tenant payment settings and returns 409 if CASH is disabled/unconfigured. Booking missing 404; owner mismatch 403; cancelled/refunded or already paid booking 409. Payable amount comes from `getPayableBookingAmount`; omitted amount defaults to outstanding amount. Non-finite, <=0, or above balance returns 400. An existing pending/processing CASH Payment for the booking returns 200 with the existing payment summary, making ordinary sequential retries nonduplicating; concurrent requests can race because there is no explicit idempotency key or transaction/unique active cash attempt constraint.

Otherwise creates Payment (provider CASH, method cash, pending status, tenant/user/customer/booking, amount and configured currency), then appends payment ID to Booking.payments if absent, sets paymentMethod CASH and paymentStatus pending, saves Booking. Success 201 `{success:true,message,payment:{id,status,amount,currency}}`; it does not establish receipt or mark paid. Staff must later confirm via a separate finance/admin workflow. Payment create and Booking save are not atomic; if booking save fails, the pending Payment remains and retry should find it. No actual cash collection is verified by this request. Controller/route: `cashPaymentController.js`, `cashPaymentRoutes.js`; lifecycle amount: `paymentLifecycleService.js`; settings: `tenantPaymentMethods.js`; model `Payment.js`. Client wrapper `createCashPayment` in `client/src/api/checkoutPaymentsApi.js`. No focused route-level test found in search; source-only review.
