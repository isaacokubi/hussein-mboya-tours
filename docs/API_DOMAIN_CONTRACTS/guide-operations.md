# Guide operations API contracts

## Entries 253–258: dashboard, assignments, guest list, tour status and reports

**Status: SOURCE-TRACED.** `server/routes/guideRoutes.js` applies `protect`, `resolveTenant`, `guideOnly` to all routes. Controller: `server/controllers/guideController.js`; models: `Staff`, `Tour`, `Booking`, `TourReport`. No focused guide-controller tests were found.

- `GET /api/guide/dashboard`: no request fields. `resolveGuide` finds or uniquely identity-matches a tenant guide Staff row, repairs its user/role/status fields, or creates a Staff profile. Reads all assigned tours (current/legacy assignment fields), populates destination/vehicle/driver, synchronizes past-end noncompleted tours to completed (database write), then rereads. Aggregates tenant booking counts/guests for confirmed/assigned/ongoing states. Returns 200 `{success:true,count,stats,tours,data:{tours}}`. Thus a dashboard GET can mutate Staff and Tour state.
- `GET /api/guide/assigned-tours`: same profile resolution (which can create/repair Staff); reads up to 50 assigned tenant tours with populated destination/vehicle/driver, synchronizes lifecycle, returns `{success:true,count,tours,data}`.
- `GET /api/guide/tours/:id`: resolves profile then checks assignment across `assignedGuide`, legacy `guide`, or `assignedTours`; returns populated `tour` and `data.tour`; missing profile/tour returns 404.
- `GET /api/guide/tours/:id/guests`: requires assignment; absent profile returns 404, not assigned returns 403. Returns tenant-scoped bookings in confirmed/assigned/ongoing/completed states, populates customer name/first/last/email/phone, newest first, as `{success:true,count,guests,data}`.
- `PUT /api/guide/tours/:id/status`: body `status` must be one of scheduled/upcoming/ongoing/completed/cancelled. Checks profile and assignment (404). Starting (`ongoing`) is limited to the local calendar start date; completing is disallowed before computed end date. Unlike the driver endpoint, controller does not enforce a strict prior-state transition table for all values. Updates timestamps/assignment status for ongoing/completed, saves using validators, and returns updated populated tour. Invalid status/date returns 400.
- `POST /api/guide/tours/:id/report`: body reads `summary`, `issues` default `[]`, and `photos` default `[]`; assignment failure returns 403. Creates `TourReport` with tenant, tour, guide, summary, issues, photos, then marks the tour completed and saves. Returns 201 `{success:true,message,report}`. Schema requires summary and defines `images`, not `photos`, so the controller's `photos` input is not persisted under the declared strict schema; no explicit validation is done before model validation. Report creation and Tour update are not transactional: a later save failure can leave the report while the tour remains unchanged. No upload/storage handler is wired for report photos on this route.

Errors not handled locally are forwarded to Express error middleware. Date transitions use server-local calendar boundaries. These contracts are source-verified; no live staff account or status mutation was used.
